Original Coding Process and Analysis

A recruiter-friendly version of the original notebook workflow: EDA, feature engineering, validation, fairness diagnostics, and metric reflection.

1. Framing the Problem

The project starts from a public-impact question: how can a county assess residential property values accurately without creating an unfair tax burden? Each row represents a Cook County residential property record with sale, structural, location, and prior assessment information.

My framing focused on market-based assessment, explainability, and the fact that average accuracy can hide systematic harm.

2. Exploratory Data Analysis

I first checked data quality, skew, and feature relationships. Sale price had implausible low values and a highly right-skewed distribution, so the training workflow filtered records below $500 and modeled log sale price. 

training_data = initial_data[initial_data["Sale Price"] >= 500]
training_data["Log Sale Price"] = np.log(training_data["Sale Price"])
training_data["Log Building Square Feet"] = np.log(training_data["Building Square Feet"])

3. Feature Engineering

I explored property size, bathrooms, neighborhood codes, prior building and land estimates, and categorical housing attributes. The final portfolio model keeps a compact, explainable feature set:

  • Log Estimate (Building)
  • Bathrooms
  • Log Building Square Feet

4. Modeling Approach

The original notebook used ordinary least squares linear regression on Log Sale Price. The refactored repo keeps that modeling path in scripts/run_model.py, with train/test-safe preprocessing so sale-price filtering is only applied to training data.

5. Validation Results

The original notebook run produced stable validation metrics:

Train RMSE:     0.6002
Holdout RMSE:   0.5937
4-fold CV RMSE: 0.6002 +/- 0.0049

Because the target is log sale price, this error should be interpreted as a multiplicative prediction error rather than a fixed-dollar error.

6. Fairness Analysis

I compared error behavior for lower-priced and higher-priced homes. The dollar RMSE was larger for expensive homes, but the overestimation rate exposed the fairness risk. 

RMSE for lower-priced homes:  about $76,899
RMSE for higher-priced homes: about $245,632

Lower-priced homes overestimated: 57.78%
Higher-priced homes overestimated: 27.69%

Since overestimated assessments can raise tax burden, the pattern suggests a regressive assessment risk.

7. Metric Reflection

RMSE is useful, but dollar RMSE is dominated by expensive homes. I explored MAPE to evaluate proportional error and make lower-priced-home errors more visible in the analysis. 

def mape(theta, X, y):
    y_pred = X @ theta
    percentage_error = np.abs((y - y_pred) / y)
    return np.mean(percentage_error)

8. Takeaway

The strongest lesson is that a model can be technically accurate and socially incomplete. A fair assessment model should combine competitive RMSE with residual parity, similar error dispersion across groups, and no consistent over-assessment of lower-priced homes.
